          Hardware benchmark
          
      
          
    
          

    
          
      
          
        
          
          
          Measures each processing stage on every backend this
            machine offers: the transcription, speaker-separation, and
            voice-matching models on the CPU and — on Apple Silicon — the Neural
            Engine (CoreML); the summarizer LLM on the GPU and the CPU. Takes a
            few minutes and needs the models downloaded. LazyMeet ships with the
            configuration that is fastest on most machines; after a run it can
            apply the combination that measured fastest on yours.
          
        
          
        
          
          How the test works
          
          By default all measurements run on synthesized
            audio and a fixed text prompt generated on the fly — none of
            your recordings are read, and nothing leaves this machine. The audio
            is deterministic noise shaped like speech; these models spend the
            same compute on every second of audio regardless of its content,
            which is exactly what differs between backends, so the comparison
            carries over to real recordings — and results stay comparable
            across machines.
          
          
          Run with your own recording uses a file you
            pick instead — capped at the first 5 minutes, decoded
            locally, never uploaded — if you want timings on your typical audio.
            Backend comparisons don't need more: their cost scales linearly with
            audio length, so more minutes only add waiting. The summarizer test
            always uses the fixed prompt.
          
          
            
            
          • Transcription — the first 120 s of the
              audio through the speech-to-text model (VAD bypassed, one warm-up
              pass first).
            • 
            
          • Diarization — a full who-spoke-when pass over
              up to 5 minutes of audio (segmentation, embeddings,
              clustering).
            • 
            
          • Speaker ID — 40 voiceprint extractions from
              5-second windows, the same way meeting voiceprints are built.
            • 
            
          • Summarizer LLM — loads the summary model and
              generates 384 tokens from a fixed prompt; the time column is the
              model load, the speed column is generation throughput.
            • 
            
          • CPU threads — all CPU stages use the thread
              count from Settings → CPU threads (default: about 75 % of
              the machine's cores); the run shows the exact number used.
            • 
          
          
          
          Times are for those fixed workloads, so runs are
            comparable across machines and backends. They are not a prediction
            of full-meeting duration — real recordings add audio extraction and
            silence removal.
